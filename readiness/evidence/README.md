# Captured local evidence

`local/report.json` was generated by the real checker from the working candidate
on baseline `490abc8`; `source_files` hashes identify exact exercised bytes even
though the candidate was not committed yet. Each check has a real test log and a
machine-readable per-test outcome JSON. These are not owner/provider attestations.

The two optional `probes` used a short-lived, test-owned
`ThreadingHTTPServer(('127.0.0.1', 0), ...)` returning `{"ok":true}` for `/healthz`
and `{"versions":["v1.11"]}` for `/_matrix/client/versions`. It was shut down after
the run. This proves the bounded HTTP probe path and response validation, **not a
running Synapse or bridge**. Production sync retry/restart is separately exercised
by `readiness/tests/test_transport.py` over its own disposable real HTTP listener.

The report records `local_checks_passed: true`, `migration_ready: false`; the
actual `--require-migration-ready` command exited **3** as required. Known history
pagination failure remains explicit in its test results. Never copy a status from
this local report into a claim of account connectivity or daily-use readiness.

Re-run with `python3 -m readiness.check --output <new-owned-directory>` for fresh
local regression evidence; provide only your own disposable endpoints if using
`--endpoints`. Ports in the captured report are historical, no longer listeners.
