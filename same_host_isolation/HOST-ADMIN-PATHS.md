# Current Oscar authority inventory — removal gates, not changes made

Inspected on this host during the same-host reference task. No secret values were collected in this document and no current agent/service/configuration was changed. This is an inventory of **actual observed paths plus explicitly marked exposed capabilities**, not a claim that every tool's implementation has been fully audited.

## Observed live host facts

- Tool commands execute as host `uid=1000(oscar)`, groups `oscar`, `sudo`, `users`; repository and host home are accessible. The active config has no explicit `terminal` section (default backend). Regardless of backend labels, these actual calls can inspect host files and operate the Docker daemon.
- `sudo -n -l` returned `a password is required`; passwordless sudo was **not** established. Oscar is in the sudo group and the runtime environment includes a sudo-password-named variable. No sudo credential was read or exercised. Do not equate `sudo -n` failing with an isolated runtime.
- Docker context is `rootless`, endpoint `unix:///run/user/1000/docker.sock`; socket mode `1660`, owned by `oscar:oscar`. Actual `docker image inspect`, `docker run`, volume/container operations succeeded. Engine reports rootless, default seccomp and cgroup namespaces. `/var/run/docker.sock` does not exist here—checking only that conventional path would miss the active management path.
- Host paths exist: `/home/oscar/.hermes/.env`, `auth.json`, `config.yaml`, `plugins/`, `skills/`; `/home/oscar/.ssh/config`; `/home/oscar/.docker/config.json`; `/home/oscar/.config/gh/hosts.yml`; `/home/oscar/runtipi`; `/home/oscar/github_repos`. Checked existence, not secret contents. Default `.ssh/id_ed25519` and `.ssh/id_rsa` were absent; this does **not** prove SSH credentials absent.
- `SSH_AUTH_SOCK` is present. Environment variable **names only** show cloud/DNS/storage, email/SMS/messaging, payment, provider/model, vault, gateway and MCP credential categories, plus terminal Docker environment/mount forwarding configuration names. Values were not inspected, serialized into this candidate, or passed into any fixture container.
- Config contains provider/browser/gateway/plugin/platform-toolset sections; MCP server names include `wizard` and `excalidraw`. It also includes API-server configuration fields. Their mere existence is not a claim that an API port is reachable or a credential works; they are additional surfaces to review. No broad reachability scan was performed.

## All execution paths must be confined or removed

| Current path / capability | Why terminal-only isolation fails | Required restricted-runtime treatment |
|---|---|---|
| `terminal`, background `process_manage`, Python `execute_code` with terminal/file wrappers | Host UID, shell/subprocess/Python can read credentials, use Docker, spawn another agent or call a provider directly. | Run every executor inside the same sandbox or remove it. No external host-command relay, unrestricted backend fallback, inherited SSH agent, Docker context/socket, `sudo`, namespace/capability escalation, or host subprocess wrapper. |
| Direct `read_file`, `write_file`, `patch`, `search_files` and corresponding Python wrappers | These are separate host-capable tools, not necessarily governed by terminal backend. Reading `.env` bypasses token isolation; editing broker/service/plugin/config bypasses immutable code. | Sandbox filesystem operations, restrict writable workspace, exclude home/app/secrets/owner volumes; no host path traversal or file upload/download deputy. Source immutable to worker. |
| `browser_exec`, browser automation/CDP helpers, shared Wizard Browser, `browser_vault`, remote browser sessions | A separately hosted browser can reach host/private APIs, access owner cookies or submit Send while worker networking is disabled. Vault autofill can confer owner authority without exposing raw password text. | Remove unrestricted browser/owner profiles/vault from restricted tool registry. If a browser is necessary, use isolated no-owner-session profiles and an independently constrained network; never expose owner console/origin/session/CDP to agent. Review browser broker as a deputy, not just worker egress. |
| `web_search`, `web_extract`, image/X/search services, URL fetches and tool-mediated requests | Remote fetchers can be alternate network/SSRF/exfiltration paths independent of container network. | Default deny or separately fixed read-only external services; forbid arbitrary URL/private-host proxy/headers/upload and ensure no sender/admin/session capability. Every broker must enforce its own narrow contract. |
| SSH config, `SSH_AUTH_SOCK`, CLI tools, private routes/tailnet, Docker context | Rootless Docker can mount host-user-readable secrets/code; SSH can escape to another unrestricted host or sender. A missing default private key says nothing about agent forwarding or alternate config keys. | No socket/config/key/env forwarding, host networking, host home, remote command bridge or unrestricted Tailnet peer. Revoke access in actual remote systems where required; do not merely hide UI tools. |
| Provider/cloud/storage/vault/payment/messaging credentials in environment, auth files, CLI configs | Direct APIs may send, mint replacement credentials, replace sender code/config, restore backups, or administer the host. | Fresh allowlisted environment; remove all provider/admin credentials and auth pools from worker. Trusted control plane holds fixed provider adapters. Any model inference relay needed by a real worker must be narrow and not confer provider-management tools or act as a general URL proxy. |
| Wizard MCP and installed app tools | Messenger send/mode/provisioning, Cloudflare action prepare/approval/resource mutation, notification/file writes, and other app routes are separate authorities. A valid broad MCP token can bypass local socket design. This session's tool catalog exposes such capabilities; not all were invoked/audited. | Restricted registry/token exposes only reviewed read/draft operations. No generic MCP dispatcher with inherited owner bearer; enforce server-side authorization per method/account/resource. Same-host network-only hiding is insufficient if a host-side tool keeps the token and acts for worker. |
| `tool_call`, `hermes_tool_search` / tool discovery, dynamically loaded integrations | Removing visible terminal access does not prevent calling a dangerous deferred tool by its exact name if dispatch remains allowed. | Enforce allowlist at dispatch/provider boundary, not in prompts or discovery results. No discoverable or hidden owner/send/admin capability callable by worker. |
| Delegation, spawned Hermes/Codex, task workers, cron/webhooks/kanban, notifications and external agents | Descendants may inherit full host toolset, credentials, owner sessions or a writable job queue consumed by a privileged executor. | Descendants inherit equal-or-less authority. Remove privileged job/delegation relays and queues; approval/resume must not silently elevate. Test actual child tool inventory, not just parent declarations. No new delegated process was used in this fixture. |
| `skill_manage`, memory/session tools, plugins, config/source writes, Git/CI/publication | Persistent instructions or executable plugin edits can influence future privileged runs; deploy/CI tokens or Git pushes can replace trusted code. This repository is public, but this source remains local. | Restricted profile and non-executable workspace only; immutable trusted plugins/source/tool registry; no deploy keys/cloud/CI authority. Never allow worker-written skills/jobs/code to execute later in owner control plane without review. |
| Gateway/API-server, owner console, recovery/bootstrap, browser handoff, secret-drop/vault | Session, password reset or recovery can become policy/admin authority even if normal Send is blocked. | Separate owner session/origin or local capability socket, out of agent reach. Do not hand worker recovery/bootstrap/owner tokens or a channel that accepts worker instructions as owner. Host console authentication is the reference's trust assumption, not a real browser/UV proof. |

The current agent can construct and dismantle the reference precisely because it still has host Docker/file/admin-adjacent channels. **It is not the restricted worker.** The proof's worker is a new, unprivileged, no-network Python container with two read-only mounts and no ambient credentials; it is not a deployed Hermes instance. Files in `same_host_isolation/` do not install an enforcement layer over existing tools.

## Acceptance gates before calling a real runtime restricted

1. Capture the exact complete enabled/deferred tool registry, all executors and descendant privileges for the new restricted instance. Reject host-side execution/file/network/owner-session deputies at the dispatch boundary.
2. Independently inspect its mounts, namespaces, environment, UID/capabilities, Docker/SSH access, MCP auth, browser profiles and network, plus cloud/deployment/backup/recovery paths. Revoke alternate provider sessions/accounts where required; credentials in trusted services may remain on the **same server**, provided worker cannot access/administer those services.
3. Repeat send/elevate/read-secret/host-file/owner-socket/Docker/host-network attacks using every real tool surface, and independently read the real provider/bridge ledger. The fixture proof is a starting acceptance pattern, not evidence for untested tool surfaces or real providers.
4. Trusted owner controls deployment and policy. Host or cloud admin intentionally granting new worker authority is outside read/draft-only guarantees. Shared-kernel/container escape vulnerabilities remain a separate threat, not an excuse to leave intentional host-admin bypasses attached.

No live cutover, account pairing, credential revocation, owner-Mac install, provider message, external publication, spending, or current service/config modification was authorized or performed.
